# Worklog 2026-09-07

## INC-14 · Closure-param forwarding (S4-fwd) — committed

- **What:** A closure-typed function parameter can now be forwarded into
  another higher-order call. `fun mapClosure<T>(values: array<T>, f: |T| -> T)
  { return map(values, f); }` called with a concrete literal — capturing or
  not — specializes `map`'s instance with its closure param bound to the
  literal's code function, and capture groups thread through the chain
  (`main → mapClosure_i → map_j → __closureN`).

- **Root cause of the pre-fix failure:** the inner `map(values, f)` call's
  closure-var argument `f` was never recorded as a `closureTarget`, because
  `closureLocals_.find(f)` did not fire during the *instantiated* `mapClosure_i`
  body — the inner call is inferred from `mapClosure_i`'s tail expression, which
  goes through `inferExpected`'s generic branch, where only closure **literals**
  (deferred) and not closure-typed **locals** produced targets. Result: `map`'s
  instance was built with `closureTargets = {}` and its own `f(x)` threw
  `closure value f was not created directly by a closure literal`.

- **Fix 1 (targets):** the `inferExpected` generic arg loop now mirrors the
  `infer` Call-case path — a closure-typed ResolvedName local that is bound in
  `closureLocals_` records a closureTarget (TS, `argument.resolvedName` Local,
  desc(parameterType) == Closure). This let the inner `map(values, f)` specialize
  `map` with `f` bound.

- **Fix 2 (capture values — the S3 runtime gap it exposed):** a capturing
  closure passed to a higher-order call did not thread its capture **values**
  into the specialized instance. Two sub-paths were missing:
  - the `infer` deferred-literal loop (`deferredClosureArgs`) recorded
    `closureTargets` only, never `callCaptures_` ⇒ `map_1_49` had a capture
    param in its signature but the caller emitted only `(values, f)` — an
    arg-count mismatch that scrambled `%p0` and crashed/killed the program;
  - the `inferExpected` closure-literal branch had the same gap.
  Both now fill `callCaptures_[&expression]` from the literal's
  `closureCaptures` (guarded by `callTargets_.find(&expression)==end()` for
  overload re-inference idempotency).

- **Fix 3 (forwarding remap):** when forwarding a closure-typed **param** of
  the current instance (not a `let f = |…|` local), the capture locals to
  thread must be the forwarding instance's own capture params
  (`instanceCaptureParamsByLocal_`), not the original closure's enclosing-local
  captures. Both the `infer` Call-case and `inferExpected` forwarding branches
  now prefer `instanceCaptureParamsByLocal_` and fall back to
  `closureCapturesByLocal_`.

- **Verification (examples):** `mapClosure([1,2,3], |x| x*2)` → `[2,4,6]`
  (12); `mapClosure(…,[factor=5]|x| x*factor)` → `[5,10,15]` (30);
  4-level `apply4→apply3→apply2` with `[offs=3]` → 7; multi-param
  `biMapF(3,4,[offs=10]|a,b| a*b+offs)` → 22; direct `map([1,2],[factor=3])`
  → 9 (S3-crash regression).

- **Tests:** `test/closure_ho_test.cpp` +6 S4 cases (forward literal, forward
  with capture, multi-level chain, multi-param + capture, direct-literal-capture
  S3 regression). Suites 32→38 closure cases. `example/closures.ng` +
  `forwardMap`/`forwardTwice` + 2 forwarding invocations.

- **Guard ceilings:** flowir.cpp held at 2203 (debug net-zero; the capture
  prepend guard was pre-existing). ast.hpp held at 966.

- **Verification:** `build/ng_test` 539/539 (3592 assertions); ctest 539/539;
  guard test green; `example/closures.ng` prints 5,31,7,16,42,42,42,42,42,82,
  84,22,20,105,2,7,50,141,18,13 (final 18 = 3+6+9, 13 = `forwardTwice` 5 with
  scale 4 → `f(f(5))` = 9+4).

- **Docs:** `09-increment-plan.md` — S4-fwd landing note (increment plan's
  original S4 "move captures + env drop" was subsumed by S3 static threading;
  this slice is the closure-param-forwarding gap the user prioritized).

- **Remaining gaps:** fully generic closure literals (plan's new S4), Fn/FnOnce
  traits + seq filter/fold (S5), differential PBT (S6).

## INC-14 · Generic closure literals (S4-generic) — committed

- **What:** A generic closure literal (`|x: T| ...` or `|T| -> T` annotated)
  inside a generic function body is now supported end-to-end. Model-time the
  closure is **type-modeled only — no code function is synthesized**; when the
  enclosing generic is instantiated with concrete types the closure body
  re-inferred and a real, lowered code function (`__closureN`) is created.
  `let f: |T| -> T = |v: T| v; f(x)` works, generic closures forward into
  higher-order calls (`map(xs, id)`), and generic closures can capture
  type-parameter locals (`[base] |v: T| base`).

- **User-directed design:** the initial proposal marked generic closure code
  functions as placeholders and *skipped their lowering*. The user objected
  ("为什么要 skip lowering…这不是个好事儿…说明你之前的 generics 也没实现完整？必须做了"):
  stubbing is a cop-out; a code function whose signature names type parameters
  must never exist at all. Final design: the synthesized code function for a
  generic closure is **deferred** until monomorphization.

- **Blocker 1 — two gates** in `typecheck_infer.cpp` threw
  `closure parameters require concrete types` for TypeParameter closure params
  (declared-annotation path in `inferExpected` ~line 884 and `infer`'s Closure
  case ~line 1775). Both removed; no test relied on the error.

- **Blocker 2 — `cloneType` dropped closure types** (`src/hir.cpp`). A
  `let f: |i64| -> i64 = …` inside a generic function never instantiated
  before: `cloneType` copied kind/span/name but not `parameters`/`result`, so
  the instance clone's binding type was a Closure with `result == nullptr` →
  `resolveWithBindings` fell through to `resolve()` → `unsupported type form`.
  This was the latent "generics weren't fully implemented" gap the user
  flagged. Fixed: `cloneType` now clones closure parameters and result.

- **Blocker 3 — model templates were lowered.** Generic function templates
  without closure-typed params were not in `placeholderFunctions_`, so their
  model bodies (which reference `|T|`-typed closure calls) were lowered as dead
  code (e.g. `identityMap_0` with a dead `__closure0_49` model closure in the
  SSA). Registration now marks **all generic templates** as placeholders
  (model-checked only; instances carry the real code) — removing the dead
  model closure output entirely. This also makes the deferred closure-call path
  (`placeholderFunctions_` guard) apply to generic closure locals.

- **Deferral mechanism:**
  - `inferClosure` returns early (no code fn, no `closureFunctions_` entry)
    when any code-param/result/capture type is a TypeParameter; the closure
    expression is recorded in `deferredClosures_`.
  - Let-bound deferred closures are recorded in `deferredClosureLocals_`
    (`typecheck_check.cpp`); calls through them in placeholder bodies take the
    existing descriptor-deferred path (extended check: parameter locals **or**
    deferred closure locals, inside `placeholderFunctions_`).
  - `inferCallClosureArgument` skips `closureTargets` recording for deferred
    closures (model not-concrete instantiation is a no-op).

- **Semantics:** generic closure bodies follow the generic-function model —
  op-free bodies (identity, selection, capture) pass; ops on type parameters
  (`|v: T| v * v`) error at model time (`binary operand type mismatch:
  expected i64, got T`), same as `fun add<T> { a + b }`.

- **Verification:** probes — `genUse<T>` → 21, `genMap<T>` (generic closure
  into `map`) → 18, `genAdd<T>` (T-typed capture) → 40, concrete closure in
  generic body → 41; `--emit=ssa` g4 clean: TP model closure gone, templates
  are empty stubs, only concrete instance chains carry code. Full suite
  544/544 (3606 assertions); closure suites 44 cases (135 assertions). Guards
  held (flowir 2203, ast.hpp 966; untouched).

- **Tests/examples:** `test/closure_ho_test.cpp` +5 positive (generic local
  call, generic local into higher-order, generic capture, concrete closure in
  generic body, op-rejection) — suites 38→44. `example/closures.ng` +
  `genApply`/`genMap`/`genCapture` + 3 invocations.
## INC-14 · S5 — Fn/FnOnce auto traits, escaping negative contract, seq filter/fold

- **seq filter/fold library-ized** (`lib/std/seq.ng`):
  - `export fun filter<T>(values: array<T>, pred: |T| -> bool) -> array<T>` —
    keeps elements where `pred` is true; reuse of the S2c `map` loop shape.
  - `export fun fold<T, U>(values: array<T>, initial: U, f: |U, T| -> U) -> U` —
    left fold threading an accumulator through the two-parameter closure.
  - No new compiler code; S2c monomorphization + S3 captures + S4 forwarding
    all compose: `myFold(values, initial, f) { return fold(values, initial, f); }`
    (forward), `[offs] |acc, x| acc + x + offs` (capture) run end to end.

- **Fn/FnOnce minimal auto-trait surface** (`lib/std/prelude.ng`):
  - `export auto trait Fn {}` + `export auto trait FnOnce {}` (empty markers,
    `export auto trait` parse path already existed).
  - `Checker::hasImpl` (`typecheck_const.cpp`): Fn-family auto traits are
    satisfied **only by closure descriptors** (TypeKind::Closure), unlike
    Send-style universal auto traits (every concrete type). So `where T: Fn` /
    `where T: FnOnce` generic functions accept closure-typed arguments and
    reject non-closures with `does not satisfy its where clause`.
  - The callable signature lives on the closure type itself; the marker only
    asserts callable-ness (no Rust-style `Fn(T) -> U` associated args in this
    slice).

- **Non-escaping negative contract** (`typecheck_check.cpp` `checkFunction`):
  - Declared return type with a Closure descriptor → clean rejection:
    `function X returns a closure, which cannot escape its scope
    (non-escaping closures, INC-14)`. Previously a no-capture closure return
    compiled (bare code-fn pointer) and a captured one referenced dead locals.
  - Nested closure literals (`|x| |y| x`) also rejected (capture contract on
    the inner body / synthesized code-fn return-type check).

- **Verification:** full suite **552/552 (3628 assertions)** (up from
  544/3606); closure suites **52 cases (157 assertions)** (+8). Guards held
  (flowir 2203, ast.hpp 966; untouched). `example/closures.ng` exit 0; prints
  filter=12, fold=15, captured fold=36, forwardFold=6, Fn-bound=5.

- **Tests/examples:** `test/closure_ho_test.cpp` +8 (filter/fold/captured
  filter/fold/forward/escape-rejected/Fn+FnOnce satisfied/Fn unsatisfied).
  `example/closures.ng` + `forwardFold`/`runBounded` + 5 invocations,
  header comment now covers S1–S5.

- **Discovered gaps (recorded, out of scope):** signature `<T: X>` trait bounds
  are NOT call-site enforced (same for `Copy`/`Send`; only `where T: X` is
  checked — pre-existing). Closure params are immutable bindings inside closure
  bodies. Closure types inside aggregates/views still rejected via the legacy
  `unsupported type form` message.
