## INC-20c S1 — std.list on Box nodes (literal/spread/traversal + builders)

`lib/std/list.ng` migrated to `Cons(head: T, tail: Box<List<T>>)`. List
contracts (literals, spreads, length/get/contains, clone/read/switch) are
green end to end; full suite **623/623 (3758 assertions)**, guard flowir at
2256/2256.

**Fix A/B — checker joins (`src/typecheck_infer.cpp`).** A file-local
`isListTail` accepts a `Box` tail (`Struct "Box"`, `typeArguments[0] ==
expected`) alongside the ref tail, at both the list-collection-literal target
(~486) and the spread-source detection (~990).

**Fix C — FlowIR spread element typing (`src/flowir.cpp`).** The EnumListGet
branch only matched `payload.elements[1].kind == Reference`; with Box tails it
matched nothing and `function_.valueTypes.at(element.value)` would throw. The
element-typing loop now accepts Ref or Box-of-source tails (net +6 lines;
exactly at the 2256 guard).

**Fix D — the migration (`lib/std/list.ng`).** Traversal reads tails
`let boxed: List<T> = read<List<T>>(ref rest)`; builders box each sutillage via
`new(rest)` (probe-validated shape, `listboxprobe3.ng`). Corpus `Fix E`:
`test/stdlib_redesign_test.cpp` + `example/std_list.ng` direct constructions
rewired to `new<List<i64>>(…)`; `list_builders.ng`/`list_literals.ng`/
`list_spread.ng` unchanged (function/literal/spread based).

**Critical deviation — literal-built boxes crashed (the planned "no lowering
change" was wrong).** Probe A (inline Box-tailed enum + `[1,2,3]`) compiled
(A/B/C typing correct) but died `invalid heap handle`. Root cause: the
literal's value-slot cells use `$ngrt_alloc` (bump arena, NOT registered in
the live table); every box op (`read`/`ngrt_load`, the clone box branch,
`release`) validates via `ngrt_handle_valid`, and only `$ngrt_allocate`
(`ngrt_live_add`) registers. Fixed in `lowering_expr.cpp` MakeRef: when the
instruction result type is a Box, emit `value=loadl(loadl(accSlot));
cell=call $ngrt_allocate(value); env=call $ngrt_alloc(16); storel cell;
storel 0,+8; result=env` — a real box (registered cell) wrapping the existing
node *word* with no deep copy, keeping the literal path **O(n)** and the
`enum.ssa`/spread walks untouched. User `ref boxLocal` still takes the
ref-object path (result type is `ref<Box>`, discriminated by result type).

**Accepted deviation — builders are O(n²) (user decision: ship + document).**
`new`/`read` are full-value deep copies at the native boundary: boxing a
k-node subtree allocates k+1 cells, reading it k; `listFromInner` re-boxes the
remaining subtree per level → quadratic (measured listFrom 1..4 → 3/8/15/24
cells). Evidence that Box VALUE copies elsewhere are shallow (share pointee):
Cons field-store +1, NG param-by-value +0, rvalue field-pick +0, struct return
+0; deep copy is confined to `clone()` and native boundaries (`new`/`allocate`
arg, `read`/`load` result). Shallow-inside-deep would alias/double-free, so
behavior is self-consistent. Real fix deferred to R6 mutating builders.
Also observed (documented, not fixed): embedded Box enum fields are not
recursively dropped (pre-existing gap); probe B's strict `outstanding()==0`
assertion was relaxed to a leak-window check.

## INC-20c S2 — list spreads via std list helpers (removed EnumList opcodes)

`EnumListLength`/`EnumListGet` FlowIR opcodes, the `$ngrt_enum_list_*`
helpers, and their native lowering cases are gone; list array-spreads now
lower as ordinary calls to std list helper instances. **Full suite 624/624
(3761 assertions)**, guard flowir 2256 → 2262.

**Design.** The std `length`/`get` take `ref<List<T>>`, which would force
flowir to synthesize a scoped-reference over a value (MakeRef + a synthetic
local, +8 lines and the ref path). Instead two **private value-taking
wrappers** carry the same walk: `spreadLength<T>(list: List<T>) -> i64` and
`spreadGet<T>(list: List<T>, index: i64) -> T` in `lib/std/list.ng`, each
delegating to `length(ref list)`/`get(ref list, index)`. Flowir passes the
list VALUE directly (element-sized ABI, no ref plumbing); the wrapper
instance's body performs the ref and re-instantiates `length`/`get`.

**Checker.** `Checker::resolveListSpreadCall(name, source, span)` scans
`module_->functions` (all modules flatten into one unit; only name visibility
is per-module — imported std functions are present) for the wrapper by name,
unifies `param0` (`List<T>`) against the spread source type, and calls
`instantiateFunction`. `unify` recurses enum variants, so `List<TP>` vs
`List<element>` binds T→element exactly like a user call; a custom chain enum
never shares the `List` nominal id → lookup fails → clean TypeError ("array
spread over `X` requires the std.list List type"). The array-literal
value-spread branch seeds `listSpreadCalls_` (spread node → {length instance,
get instance}), moved into `TypeCheckResult.arrayListSpreadCalls` at
registration.

**FlowIR.** Both emissions swap to `Evaluate Call` (`callTarget` = the
instance; length operand = `source`, get operands = {source, indexRead}); the
`ArrayLength`/range paths are untouched. Proven lowering template: map spreads
already emit `Evaluate Call`, and `lowerCall` resolves NG/instance targets via
`symbolFor`.

**Removals.** `include/flowir.hpp` opcodes + comments; both cases in
`src/native/lowering_expr.cpp`; `src/native/helpers/enum.ssa` contained only
the two list helpers → deleted, `CMakeLists.txt` drops it from
`NG_HELPER_SSA`.

**Accepted scope note.** A structurally list-shaped custom enum (Cons/Nil +
Box tail) previously spread via the structural walkers; after S2 it is
rejected at check time (clean std.list-required error). Not used by any
corpus/example; documented in the plan.

**Tests.** +1 IR-absence case in `test/stdlib_redesign_test.cpp`
(`--emit=ssa` on a list spread → output contains no `ngrt_enum_list`).
Verification: `[Stdlib]` 24 cases / 96 assertions, `[Guard]`, non-example
suite 591/3477, examples sweep 33/284 → **624/624 (3761 assertions)**.
Probes: `probe_s2.ng` (plain + mixed + empty spreads, indexing) → exit 0,
`return 7`; custom `Chain<T>` spread → `type error ... requires the
std.list List type`.
