# Worklog 2026-08-25

## 17:03 CST — Fixed Linux CI failure in the imgui compile/link driver test

- **What:** Reordered the native link line so `libngrt.a` comes last (after `libngrt_imgui.a`, `libimgui.a`, `libSDL3.a`) in `src/driver.cpp`. Also added the missing `<algorithm>` include to `src/hir.cpp` and `<format>` include to `src/driver.cpp`, and added a Catch2 `INFO(...)` diagnostic to `test/driver_test.cpp` so future failures print the driver status/output/errors.
- **Why:** The new test from `7a4a2f0` ("compiles and links an imgui program without running it") failed on GitHub's ubuntu runner with an opaque `1 == 0`. Root cause: GNU ld resolves static archives in a single left-to-right pass; for programs whose generated code never references `libngrt.a` directly, its members were discarded before the linker discovered `libngrt_imgui.a`'s `ngrt_new_string` dependency → `undefined reference` → exit 1. macOS's newer linker re-scans archives, masking the bug locally.
- **Verification:** Reproduced in a Docker replica of the CI environment (ubuntu 24.04, clang-20, no X11/Wayland dev packages); observed the real linker error after surfacing it manually via `ngi --output`. After the fix: full suite green locally (455 cases / 1940 assertions, macOS arm64) and in the container (455 cases / 1940 assertions, linux/arm64).

## Postmortem — imgui link test failure on Linux CI

- **Impact:** One failing test case blocked the `build` workflow; the failure output gave no actionable information.
- **Timeline:** Test introduced in `7a4a2f0` (local macOS green) → CI run failed at `./ng_test` → reproduced in Docker by mimicking the runner (apt clang-20, `RUNNING_ON_GITHUB=true`, no X11/Wayland) → root cause identified from the previously hidden stderr → fixed, verified both platforms.
- **Root cause:** Link-order sensitivity of one-pass static linking (GNU ld), combined with platform-divergent linker behavior (ld64 re-scans).
- **Contributing factors:**
  - The test captured `errors` into a string but never printed it on failure, hiding the linker message from CI logs.
  - Local-only verification on macOS cannot catch GNU ld semantics; there is no Linux check before push.
- **Actions taken:** archive-order fix with explanatory comment; test diagnostics via `INFO`; missing standard includes fixed (latent portability bugs found while reproducing under libstdc++).
- **Remaining gaps / suggestions:**
  - Consider running the suite in a Linux container (or adding a second CI job/arch) before push for linker/platform-sensitive changes.
  - Other driver tests still swallow `errors` on failure; extending the `INFO` pattern would make future CI failures self-explanatory.
