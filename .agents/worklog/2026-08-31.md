## INC-14 · S1 minimal closures — syntax, explicit typing, direct calls (committed)

- **What:** Implemented the forward-pulled INC-14 S1 closure slice end to end
  (parser → resolver → typechecker → FlowIR → native). Commits:
  `ffae039` `feat(vnext): INC-14 S1 minimal closures …` and
  `bc4729a` `docs(vnext): INC-14 S1 closure slice …`.
- **Syntax:** `ClosureExpression` AST node + `ExpressionKind::Closure`; parser
  `parsePrefix` routes a leading `|` to `parseClosure` (explicit `|x: i64|` heads
  via `parseTypeUntil({Comma, Pipe})`, `{...}` bodies via parser-local
  `consumeBlockTokens` re-sliced through `BlockParser`, expression tails otherwise).
- **Resolver/HIR:** closure param names/ids/types + body on `hir::Expression`;
  params declared in a pushed scope; missing param type → resolution error
  ("requires a type annotation").
- **Typechecker:** `TypeKind::Closure` (params in `elements`, result in `element`)
  + `internClosure`. Each closure literal synthesizes a unique code function
  (`__closureN`, DefId = `functions.size() + instances_.size()` at append): body
  deep-cloned + param locals remapped via new public `hir::makeClosureFunction`,
  re-checked through `instances_`. Calls through closure-typed locals reuse the
  existing `callTargets` side table (callee → code DefId); no new results table.
  `closureLocals_`/`closureFunctions_`/`closureCounter_` internal maps drive it.
  Negative contracts: explicit param types required; non-param-local references →
  `closure would capture local N; captures are not yet supported (INC-14 S3)`
  (walker excludes statements' own bindings: local/destructured/rest/loop/switch).
- **FlowIR/native:** extended `directCall` to skip the callee local operand for
  closure calls; closure literal lowers to an inert zero word; `qtypeOf` maps
  Closure → `QType::Long`.
- **Parser fix (general):** `BlockParser::parseExpressionUntilAny` was missing the
  `braceDepth == 0` guard on its primary terminator break, so a `;` inside a
  block-bodied closure truncated let-initializer slices ("expected `}` to close
  closure body"). Now mirrors the ModuleParser depth-tracking behavior.
- **Leaves for later slices:** `||` (zero-param head) lexes as logical-or — S2
  disambiguation; generic/type-inferred params (S2), captures (S3/S4), Fn traits
  (S5), differential PBT (S6). Block-body closures that reference enclosing locals
  correctly reject in S1 (they are captures).
- **Tests:** `test/closure_test.cpp` — 12 cases: parse heads (single/multi/omitted
  type), block bodies, native calls (incl. block body, tailless Unit side-effect
  closure via print, helper-function scope), negative contracts (arity/type/capture),
  `example/closures.ng` E2E. `example/closures.ng` adds a runnable example (add/mul/
  block-body/plan/apply), swept by `examples_sweep_test`.
- **Guard:** flowir.cpp 2149→2177, ast.hpp 925→938 → ceilings raised with written
  justification in `test/guard_test.cpp`.
- **Verification:** `build/ng_test` 512/512 (3511 assertions); `ctest` 513/513;
  `build-asan/ng_test` 512/512 (3511 assertions). Note: ASan full runs occasionally
  trip a pre-existing UBSan flake in `test/integer_overflow_test.cpp:123` via the
  `pbt.hpp` differential harness (seed-dependent; passes in isolation and on reruns;
  last touched `f448fe4`, unrelated to closures).
- **Docs:** `09-increment-plan.md` — swap decision + S1–S6 slices + S1 landing note
  (`docs(vnext): bc4729a`).
## INC-14 · S2 first half — `||` zero-param heads + expected-type-driven inference + tail-return fix (committed)

- **Commits:** `777651d` `feat(vnext): INC-14 S2a+S2b …`, `ed2e18c` `docs(vnext): …`,
  `2a0d879` `chore(agents): …`.

- **What:** S2a+S2b of the INC-14 closure slice: zero-parameter `|| expr` closure
  heads, expected-type-driven parameter inference for untyped closure parameters,
  the `|T| -> R` closure type literal, and a latent fallthrough-return bugfix
  exposed by `|| 7`.
- **Syntax/type language:** `parsePrefix` now routes a leading `OrOr` to
  `parseClosure` as an empty parameter head (`|| 7`). New `ClosureTypeSyntax`
  AST node (`|T, U| -> R`, result mandatory) handled by `TypeParser::parsePrimary`
  (extracted shared `parsePostfix`), lowered via `hir::TypeKind::Closure` +
  `hir::Type` `parameters`/`result` fields (`lowerType` + `renderTypeName` +
  `cloneType`), interned through `TypeInterner::internClosure`.
- **Resolver/HIR:** omitted closure parameter annotations are allowed (nullable
  `closureParameterTypes`), moving the "untyped parameter" error to the checker.
  `makeClosureFunction` tolerates a null declared type (from the inferred case).
- **Typechecker:** `infer`'s Closure case refactored into `Checker::inferClosure`
  (body check + code-function synthesis + `internClosure`), reused by a new
  `inferExpected` Closure branch that derives parameter types from the expected
  closure descriptor; the branch now also `record`s the closure expression type
  (missing `record` was an `unordered_map::at` crash in flowir's `typeIdOf`).
  Untyped parameters with no expected type → clean "cannot infer closure
  parameter" error; result-type mismatch → clean expected-vs-actual error.
- **Latent bugfix (FlowIR):** value-typed function bodies whose last statement is
  a bare tail expression lowered to an empty `ret` (QBE leaves a leftover
  register), which S1 closure tests only survived because the value happened to
  land in the return register. `|| 7` exposed it. `FunctionLowerer` now records
  the function-body tail value (`functionBody_` guard, non-Unit declared result)
  and feeds it into the fallthrough `Return` terminator — `fun f() -> i64 { 42 }`
  now returns 42.
- **Tests:** `test/closure_test.cpp` 12→15 cases (zero-param `||` head, S2
  expected-type inference ×2, result-mismatch negative, untyped-without-context
  negative; the old "requires a type annotation" contract replaced by the S2
  message). `example/closures.ng` extended with `|| 42`, typed-let inference,
  multi-param inference.
- **Verification:** `build/ng_test` 515/515 (3525 assertions); `ctest` 516/516;
  `build-asan/ng_test` 515/515 (3525 assertions) — no UBSan flake this round.
- **Docs:** `09-increment-plan.md` — S2 landing note appended.
- **Guard:** flowir.cpp 2177→2185 and ast.hpp 938→955 raised with written
  justification in `test/guard_test.cpp`.
