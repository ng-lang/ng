## INC-14 · S1 minimal closures — syntax, explicit typing, direct calls (committed)

- **What:** Implemented the forward-pulled INC-14 S1 closure slice end to end
  (parser → resolver → typechecker → FlowIR → native). Commits:
  `ffae039` `feat(vnext): INC-14 S1 minimal closures …` and
  `bc4729a` `docs(vnext): INC-14 S1 closure slice …`.
- **Syntax:** `ClosureExpression` AST node + `ExpressionKind::Closure`; parser
  `parsePrefix` routes a leading `|` to `parseClosure` (explicit `|x: i64|` heads
  via `parseTypeUntil({Comma, Pipe})`, `{...}` bodies via parser-local
  `consumeBlockTokens` re-sliced through `BlockParser`, expression tails otherwise).
- **Resolver/HIR:** closure param names/ids/types + body on `hir::Expression`;
  params declared in a pushed scope; missing param type → resolution error
  ("requires a type annotation").
- **Typechecker:** `TypeKind::Closure` (params in `elements`, result in `element`)
  + `internClosure`. Each closure literal synthesizes a unique code function
  (`__closureN`, DefId = `functions.size() + instances_.size()` at append): body
  deep-cloned + param locals remapped via new public `hir::makeClosureFunction`,
  re-checked through `instances_`. Calls through closure-typed locals reuse the
  existing `callTargets` side table (callee → code DefId); no new results table.
  `closureLocals_`/`closureFunctions_`/`closureCounter_` internal maps drive it.
  Negative contracts: explicit param types required; non-param-local references →
  `closure would capture local N; captures are not yet supported (INC-14 S3)`
  (walker excludes statements' own bindings: local/destructured/rest/loop/switch).
- **FlowIR/native:** extended `directCall` to skip the callee local operand for
  closure calls; closure literal lowers to an inert zero word; `qtypeOf` maps
  Closure → `QType::Long`.
- **Parser fix (general):** `BlockParser::parseExpressionUntilAny` was missing the
  `braceDepth == 0` guard on its primary terminator break, so a `;` inside a
  block-bodied closure truncated let-initializer slices ("expected `}` to close
  closure body"). Now mirrors the ModuleParser depth-tracking behavior.
- **Leaves for later slices:** `||` (zero-param head) lexes as logical-or — S2
  disambiguation; generic/type-inferred params (S2), captures (S3/S4), Fn traits
  (S5), differential PBT (S6). Block-body closures that reference enclosing locals
  correctly reject in S1 (they are captures).
- **Tests:** `test/closure_test.cpp` — 12 cases: parse heads (single/multi/omitted
  type), block bodies, native calls (incl. block body, tailless Unit side-effect
  closure via print, helper-function scope), negative contracts (arity/type/capture),

  the `|T| -> R` closure type literal, and a latent fallthrough-return bugfix

  `inferExpected` Closure branch that derives parameter types from the expected

## INC-14 · S2c higher-order closures + std.seq `map` (committed)

- **What:** Higher-order functions: closure-typed function parameters act
  semi-generic — every concrete closure argument produces a closure-specialized
  instance, so `f(x)` inside the re-checked body binds to the literal's
  synthesized code function. `lib/std/seq.ng` gains `export fun map<T, U>`.
  Commit to follow this entry (`feat`/`docs`/`chore`).
- **Design:** closure-typed signature parameters make a function a template: the
  ORIGINAL is marked in `placeholderFunctions_` at registration (driver lowers it
  only as a stub Return — it is never called; instances carry the real code), and
  its body is type-modeled by a deferred path. `instantiateFunction` takes
  `closureTargets` (param index → code DefId); the gate is
  `!isGeneric(signature) && closureTargets.empty() → return original`, the key
  appends `|cl{index}#{defId}` so distinct closure arguments (even under equal
  substitutions) yield distinct instances, and — after clone — the parameter
  local is bound via `closureLocals_.emplace(clone.parameters[index].local.value,
  defId)` BEFORE re-checking, so the instance's `f(x)` resolves as a direct call.
- **Checker paths added:** (1) closure-call branch — when the callee is a
  parameter local of a placeholder-marked current function, type the call from
  the closure descriptor (`type = closure.element`), do NOT record `callTarget_`
  (template-body deferred path); otherwise S1's `closure value \`x\` was not
  created directly by a closure literal` still throws. (2) `analyzeCallSpread` —
  closure-literal arguments no longer eagerly inferred (empty slot) so
  `inferExpected` can drive T/U first. (3) `inferExpected`'s generic-call branch —
  closure literals are typed via the shared `Checker::inferCallClosureArgument`
  (specialize parameter type, arity-check, infer elements, record, unify),
  collecting `closureTargets`, threaded into `instantiateFunction`; closure-var
  args (typed let bindings with a `closureLocals_` DefId) are collected in the
  main generic loop too. (4) `TypeInterner::specialize` + `unifyGuarded` got
  Closure cases (structural param/result specialization/unification).
- **Parsing fix:** `ModuleParser::parseTypeUntil` token collector stopped at ANY
  top-level terminator, so the comma inside `|i64, i64|` truncated closure
  parameter types in function signatures ("expected `|` to close closure
  parameter types"). Pipe depth now nests like angle brackets: `|` at a
  type-start (first token, or after `(`,`,`/`<` inside type collection) opens, its
  matching `|` closes, and terminator commas inside are kept. Let-annotation path
  was unaffected (single `=` terminator).
- **Tests:** `test/closure_ho_test.cpp` — 10 cases: non-generic `apply(f,x)`,
  generic `applyTwice<T>` (f(f(x)) → 84), closure-typed local argument, block-body
  and multi-param closure arguments, nested call through closure, unused
  higher-order template type-checks as a placeholder, template closure-arity
  negative, closure-alias S1 contract preserved, `seq.map` E2E (20). Closure suites
  now 15→25 cases / 82 assertions. `example/closures.ng` extended (+6 groups:
  closure literal arg, closure-typed local arg, twice ×2 distinct closures,
  `map` over `[1,2,3,4]` → 20).
- **Verification:** `build/ng_test` 525/525 (3553 assertions); `ctest` 526/526;
  `build-asan/ng_test` 525/525 (3553 assertions, clean rerun after the known
  `test/pbt.hpp` UBSan flake); guards unchanged.
- **Docs:** `09-increment-plan.md` — S2c landing note appended.
