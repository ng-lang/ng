# Worklog 2026-09-01

## INC-14 · S3 copy/move captures + static capture threading (committed)

- **What:** Copy and move captures with explicit capture lists, threaded
  statically (no runtime env carrier). Code functions and higher-order
  specializations receive hidden leading capture params. Commits follow.

- **Syntax/resolver:** `Expression::CaptureInfo{local, isMove}` + a new
  `closureCaptures` list on the closure expression. Capture names are resolved
  to enclosing-local ids in the HIR resolver, and each capture name is shadowed
  by a fresh closure-body-scope local (`closureCaptureParams`), so the body
  reads the capture param — not the enclosing local directly. The synthesized
  code function (`__closureN`) prepends capture params (`__cap{i}`) via
  `makeClosureFunction`'s remapLocal; `cloneExpression` clones both new fields.

- **Checker:** `inferClosure` validates captures, types capture params from the
  enclosing locals, checks the body against the capture params, marks move
  captures (whole value) only AFTER the body check, records
  `closureCaptures_`/`closureCaptureTypesByFunction_`, then synthesizes code
  params `captureTypes ++ parameterTypes`. `ensureNoCapturedLocals` → new
  `validateCaptures`: params + capture params are in scope; an uncaptured
  enclosing-local reference errors `closure body references local N which is
  not listed in the capture list`. `TypeCheckResult` gained `callCaptures`.

- **Direct call-site threading:** FlowIR prepends each capture value as a
  leading operand using a synthetic `ResolvedName` Evaluate instruction whose
  payload is the capture local id (a raw `ValueId{captureLocal}` was wrong for
  arrays — local ids are not value ids). Emits once per call via the
  `directCall && callCaptures.contains(&expression)` guard.

- **Higher-order threading:** `instantiateFunction` prepends capture groups
  (`__instance_capN`), in `closureTargets` order, to the instance's clone
  parameters and `instanceSignature.parameters` (insert position
  `capturePrefixCount`); records `instanceCaptureParamsByLocal_` so the
  instance's internal closure call prepends them, and `shiftedClosureBindings`
  → `closureLocals_` for the re-checked body.

- **Idempotency bugfix (the S3 blocker):** overload resolution re-infers the
  same call expression once per candidate — a `print(apply(f,5,7))` arg was
  inferred 15× (12+ print overloads), re-appending one capture group per pass
  and producing an 18-operand call → wrong result **300** instead of **112**.
  The higher-order capture record is now guarded by
  `callTargets_.find(&expression) == callTargets_.end()` (only the first
  inference accumulates), restoring `apply(f,5,7)` → **112**. Verified by
  backtrace: identical `[checkStatement, infer, infer]` stack at depth 2 each
  pass, instances 1→2 frozen, `nextInst` constant.
