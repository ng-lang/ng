# 2026-09-15

## INC-20c precursor — Box-in-aggregate fixes + Box-list feasibility

Two real memory bugs fixed (committed `11bcc48`), a probe-misdiagnosis
corrected, and the Box-list std migration validated end to end.

**Fix 1 — Box moved into an aggregate literal releases its cell twice.**
`inferExpectedEnum` (tuple + single-payload branches) and `inferExpectedStruct`
in `src/typecheck_infer.cpp` never called `trackConsumption` on payload
arguments, so `let p: Pair = Pair.Cons(1, t)` left `t`'s scope-end drop edge
alive. At the switch-arm return path both `t` and the pattern-bound `b` released
the same cell → `ngrt_release(invalid heap handle)`. Added `trackConsumption`
after each payload-arg `inferExpected` (7 lines). `boxpattern.ng`/
`boxpattern3.ng` no longer double-release; `boxm2.ng` still rejects reuse.

**Fix 2 — whole-moved Box locals dangled payload tokens in `boxrec.ng`.**
Consumption marking flipped leaf/inner from heap cells (`ngrt_alloc(8)`) to the
stack-slot fast path (`alloc8 8`). A box VALUE is an address to an 8-byte cell
holding the handle; a stack slot is reused once the binding dies, so every
aggregate payload token pointing at it went stale → `read(ref other)` returned
wrong fields in-process. `collectLocals()` now seeds `cellLocals_` for every
Box-typed local (8 lines). Recursive clone passes in-process again; probes +
full suite 623/623 under both normal and ASan builds.

**Probe-misdiagnosis (no code change).** `new<List<T>>(tailLocal)` and nested
`List.Cons(...)` construction initially failed with `E-type expected List, got
List`; instrumented the interner (`[enum-resolve]`/`[enum-spec]` traces) and
proved the ids matched — the probe had typed a `listLength<T>(list: List<T>)`
call as `listLength<List<i64>>(root)` (wants `List<List<i64>>`) instead of
`listLength<i64>(root)`. Also learned the reassignment operator is `:=`, not
`=`, in blocks/switch/loop bodies. No interner change.

**Box-list feasibility (INC-20c S0 prototype).** `/tmp/listboxprobe3.ng`
mirrors the production std.list shape on `Cons(head: T, tail: Box<List<T>>)`
with fully implicit generic inference — `length`/`get`/`contains`/`listFrom`/
`listFromInner` (recursive)/`pushFront`/`append`/`reverseList` all green, exit
0, single allocations per node via `new`. So the std migration needs no
call-site annotation changes.
