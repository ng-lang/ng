# 2026-09-11

## INC-19 S1 — generic `Box<T>` + `new`（DEC-C/B1 核心）

- **Purpose**: B1 core heap-cell slice — generic single-owner affine
  `Box<T>` over a session-owned native handle table (per DEC-C: affine Box
  goes through an owning handle; Copy aggregates share via refcount+CoW later).
  No GC; each cell lives in the bump arena (INC-18) and the owning `Box<T>`
  releases it drop-exactly-once under the checker's affine move rules.

- **`lib/std/memory.ng` rewrite** (generic natives + generic Drop):
  - `type Handle = native`; `export native fun allocate<T>(value: T) -> Handle`,
    `load<T>(handle: Handle) -> T`, `store<T>(handle: Handle, value: T) -> unit`,
    `release(handle: Handle)`, `outstanding() -> i64`.
  - `export struct Box<T> { handle: Handle }` + `export impl<T> Drop for Box<T>`
    (`release((*self).handle)`).
  - `export fun new<T>/box<T>/read<T>/write<T>` — each **spells the generic
    argument explicitly** (`allocate<T>`, `load<T>`, `store<T>`).

- **Cross-parameter generic-call limitation (root cause, probed)**:
  a generic function cannot pass its type parameter as an implicit call
  argument into another generic callee — `unifyGuarded` has no Struct arm, so a
  type-parameter-in-argument-position unifies only if the interned TypeId is
  identical (self-recursion); otherwise "generic argument type mismatch:
  expected W, got W" (two distinct struct ids). **Explicit call arguments
  work** (`one<T>(v)` compiles/runs), so the stdlib wrappers spell `<T>`.
  Documented in `memory.ng` header and 09-increment-plan.md.

- **Checker additions**:
  - `unifyGuarded` — new `TypeKind::Struct` arm mirroring the Enum arm
    (nominalId + type-argument count + per-argument unify); enables
    `write(ref b, 9)` inference (unify `Box<T>` with `Box<i64>`).
  - `registerImpls` — the Drop branch now registers **generic** Drop impls
    (pattern + typeParameters + placeholderFunctions_ + ImplInfo generic=true),
    previously "unknown type `T`".
  - `dropEdge` — locates a concrete-or-generic Drop impl via `matchImplPattern`
    and `instantiateFunction` for the generic case; new `hasDrop(TypeId)`
    replaces the `dropTypes_` guards (member removed, `test/guard` updated? no
    guard change — the `dropTypes_` member was internal only).
  - `instantiateFunction` — instance signature now registered in
    `functionTypeIds_` (before the `signatures_.emplace` move); previously
    instances had no `functionTypeIds_` entry, so FlowIR `lowerDropCalls`
    (flowir.cpp ~1503-1533) could not type the injected MakeRef/call operands
    for a generic-drop instance → "internal error: missing operand type" at
    QBE lowering. This was the S1 blocker.

- **Payloads**: 64-bit word path — i64/string/array/struct/enum/tuple and f64
  round-trip bit-preservingly (whole word store/reload, no numeric
  interpretation at the handle; DEC-A is the checked-numeric redesign). No
  aliasing: deep copy on write (native shim) and on read (bind).

- **Verification**. `test/box_test.cpp` `[Box]` `[INC19]` (6 cases): word
  payload round-trip (i64/string/array/struct), box<T> alias + f64/f32
  bit-preserving, write-snapshot non-aliasing, affine move + drop-exactly-once
  (`outstanding()`), loops + early-return release accounting, and a negative
  compile contract (`use of moved value`). `example/box.ng` (corpus sweep)
  returns 0 with per-line failure markers. **Known migration**: the old
  single-typed memory natives are gone, so the INC-18 E2E probe
  `test/probes/arena_all.ng` and one stdlib fixture now call the natives with
  explicit generics (`allocate<i64>`/`load<i64>`/`store<i64>`) — full-suite
  exposure rerun green. Full ng_test 620/620 (3749 assertions), ctest 621/621.

- Limits (documented): no Gc/Arc/allocator params yet (deferred to R6); generic
  call inference cannot carry a type parameter across a callee boundary (fixed
  by explicit args); floats are bit-preservation only (no checked numeric
  semantics until DEC-A).

- Commits: `feat(vnext)`, `docs(vnext)`, `chore(agents)`.
## INC-20a — affine-enum switch consumes scrutinee (keystone for INC-20)

- **Purpose**: the migration of `std.list` onto `Box` (INC-20) is blocked until
  a switch over an affine enum value consumes its scrutinee. Probes showed
  that with a Box payload, `switch (one)` (by-value affine enum) and
  `switch (*x)` (deref) trigger double-releases once any Box binding drops.

- **Fix**: `checkSwitch` (typecheck_check.cpp) now calls
  `consumeSwitchScrutinee(*statement.expression, locals, beforeSwitch)` when the
  scrutinee type is affine (`isAffine`). The helper mirrors `trackConsumption`
  (Grouped unwrap, ResolvedName→Local `markWhole`, Member→field `markField`,
  borrow-conflict throw) but **never throws E-move-partial**: a partial move
  inside an arm is subsumed by the switch consumption. Because drop-edge tables
  (`blockDrops`/`fallthroughDrops`/`returnDrops`) gate on
  `moveState_.isWholeMoved`, the scrutinee's scope-end drop is suppressed.

- **Probe**: `enum Cell { Cons(head: i64, tail: Box<Cell>), Nil }`,
  `let leaf = new<Cell>(Cell.Nil)`, `let root = new<Cell>(Cell.Cons(1, leaf))`,
  `switch (read(ref root))` → head extracted = 1, `outstanding()` held at 2,
  exit 101. No invalid-heap-handle crash.

- **Verification**: `ng_test '~[QBE]'` 573/573 (3558 assertions), ctest 621/621.
  (The `[QBE]` native toolchain suite has 2 pre-existing infra failures: fib/tail
  recursion timing out under SIGTERM — unrelated to this change.)

- **INC-20 blocker (probe conclusion)**: `read`/`load` of a Box cell containing
  nested Box tokens shallow-copies the handle words (materialized value sees an
  alias copy). `hasDrop(type)` only recognizes explicit `impl Drop`, so a Box
  field inside a struct/enum without a Drop impl is **never released
  (leak)** — demonstrated: returning from a callee that owns
  `struct Wrap { b: Box<i64> }` leaves `outstanding()` +1. Therefore:
  - non-destructive list iteration (`switch (*list)` / `length(ref xs)` /
    `read(ref b)`) is unsound under Box tails;
  - the destructive consume path is sound only when each cell's ownership is
    linearly transferred (no duplicate named owners) — which the current
    box/allocate/read/store primitive set cannot express cleanly.
  Fix options recorded: (a) `Box.clone` deep-copy + consuming source access;
  (b) INC-22 `Handle` 式内部可变性; (c) destructive-only List API (changes
  contract source). None are fully in INC-20's current primitive scope — the
  increment is parked pending a direction decision.
