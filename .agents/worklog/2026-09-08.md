# 2026-09-08

## INC-12 — prelude Option<T>/Result<T,E> + combinators + law PBT

- **Purpose**: stdlib slice (no new compiler code) giving NG the Option/Result
  pair after INC-14 landed first-class closure transforms.

- **What landed (lib/std/prelude.ng):**
  - Two prelude generic enums: `enum Option<T> { Some(value: T), None }` and
    `enum Result<T, E> { Ok(value: T), Err(error: E) }`.
  - `parseInt(text) -> Result<i64, string>` (Ok on `canParseInt`, Err carrying
    the offending text); legacy `OptionalInt` enum removed. All uses migrated:
    `example/int_string.ng`, `test/string_conversion_test.cpp`, trap-note text.
  - Combinator family over both enums, clause-typed transform args:
    `optMap`, `optAndThen`, `optOrElse`, `resultMap`, `resultAndThen`,
    `resultOrElse`.

- **Naming decision (deviation from the plan, documented in increment plan):**
  the plan named them map/andThen/orElse, but `seq.map` already owns `map`.
  Empirically, a same-name generic overload across modules selects one
  candidate silently — with a local Option-`map` present, the array call
  `map(xs, ...)` dies with `expected Opt, got array<i64>` (no ambiguity error).
  opt/result prefixes de-collide; combinator semantics preserved.

- **Law PBT** (`test/option_result_test.cpp`, INC-1 harness, 60 trials × 8
  probes = 480 probes, one batched module): Option identity
  (`optMap(o, |x| x) == o`), Option composition on Some and None,
  `optOrElse` default-on-None and keep-on-Some, Result composition on Ok and
  Err. Values bounded to [-6, 6] and transforms affine-positive so checked
  arithmetic cannot trap. Green across 4 seeds.

- **NG gaps surfaced along the way (all pre-existing, out of INC-12 scope,
  worked around in-probe):**
  1.  Non-generic functions with a concrete generic-enum parameter
      (`fun f(o: Option<i64>)`) are uncallable (`no matching function
      specialization`). Combinators are therefore generic; helpers cannot be
      written concrete.
  2.  Generic function bodies are checked wholly at model time (an `i64`-op on
      a type parameter errors), so law equality must live inline in the probe
      body at concrete types.
  3.  No `derive(Eq)` for generic enums, and `enum X: derive(...)` isn't
      parsed — law comparisons reduce to nested `switch` + concrete `i64 ==`.
  4.  Nullary/assorted enum constructors lack expected-type inference in
      argument/switch positions (`Option.Some(5)` directly there → `cannot
      infer generic arguments for enum constructor`); bind through an
      annotated `let` first.
  5.  Block-closure bodies are tail-expression style — explicit `return`
      inside a block-closure (`{ ...; return r; }`) fails (`expected
      <invalid>, got ...`); use `{ let r: Option<T> = ...; r }`.

- **Contract example** `example/option_result.ng`: parse Ok/Err switch,
  optMap + composed transforms, optAndThen None short-circuit, optOrElse
  default, resultMap Ok path, resultOrElse Err recovery — 8 printed `true`s.

- **Verification**: full suite 554/554 (3634 assertions); ctest 555/555;
  guards held (flowir 2203, ast.hpp 966 — untouched, stdlib-only slice).

## INC-13 — `?` try-operator desugar (D-007 landing)

- **Purpose**: first compiler change for the D-007 error model — `expr?`
  desugars on the HIR side into switch + early-return, so the checker's three
  drop-edge tables (fallthrough/block/return) and FlowIR switch/return
  lowering apply unchanged (native backend is untouched).

- **What landed (compiler + tests + example):**
  - `include/syntax/ast.hpp`: new `TryExpression` node + `ExpressionKind::Try`.
  - `src/syntax/parser.cpp`: postfix `?` disambiguated by lookahead — an
    immediately-following `...` keeps the map-spread filter marker semantics
    (`f(xs)?...` unchanged); anything else parses as the try operator
    (`TryExpression`). No bare-`?` existed in the corpus, so nothing else moved.
  - `src/hir.cpp` `Resolver::desugarTry`/`resolveStatementList`/`rootTryOf`:
    `let x = expr?;` is restructured into

    ```
    let $tryN = expr;
    switch ($tryN) {
        case Ok($okN) { let x = $okN; <rest of the block> [tail] }
        case Err($errN) { return Result.Err($errN); }
    }
    ```

    Supported root forms: `let` initializer (annotation / `let mut`
    preserved), bare statement `expr?;`. Function-body tails move into the Ok
    arm as an explicit `return` (only the top-level function/method body
    treats a tail as the implicit return — if/loop-branch tail semantics are
    unchanged). Nested `?` recurses through the Ok arm via
    `resolveStatementList`. Synthesized names use `$` prefix (the lexer cannot
    produce `$`, so user collisions are impossible).

- **Differential PBT** (`test/try_operator_test.cpp`, INC-1 harness): 2-step
  and 3-step chains plus a drop-edge variant (a live string local before the
  first `?`) compare `?`-form vs hand-written nested-switch expansion on
  property-generated inputs; 60 trials × 3 probes batched, green across 4
  seeds.

- **Negative contracts** (clear E-resolve messages): non-Result return
  (`i64`/`unit`), `return <expr>?`, mid-expression (`g()? + 1`), closure body,
  destructuring `let` — all explicitly rejected in INC-13 scope.

- **Contract example** `example/try_operator.ng`: parse → validate → compute
  chain via `parseInt` + positive/even guards + `?`; 4 printed `true`s
  (Ok flow, two validation Err paths, parseInt failure carrying its text).

- **Verification**: full suite 560/560 (3662 assertions); ctest 561/561;
  guard updated for the new syntax node (ast.hpp 966 → 977); flowir 2203
  untouched; INC-12 and INC-13 PBT suites green across 4 seeds each.

- **INC-13 boundary (documented in the increment plan, for later slices)**:
  `?` is limited to let/statement roots; mid-expression, `return <expr>?`,
  closure bodies, and destructuring lets are rejected rather than partially
  supported.

## INC-15 — origin contracts 与返回引用（D-002 A1.1）

- **Grammar**: `ScopedReferenceTypeSyntax` gains a `origins` list; in postfix
  `ref` parsing, `T ref(a)` / `T ref mut(a | b)` parses a `(` name (`|` name)*
  `)` origin list after the `ref` (distinct names, pipe-separated).

- **Resolution**: `Resolver` now tracks a per-function `paramOrdinals_`
  (parameter name → declaration ordinal) while lowering parameter/return
  types in `resolveFunction` / `resolveTraitMethod`. `lowerType` takes the
  map (nullable) and, for a scoped reference with an origin list, resolves
  each origin name to its ordinal via `resolveOriginOrdinals`, storing them on
  the HIR `Type.originOrdinals`. Non-parameter origins are rejected with
  `reference origin \`x\` is not a parameter of the enclosing function`.
  `cloneType` preserves `originOrdinals` (monomorphization-safe).
  `renderTypeName` now prints `T ref(a | b)` for diagnostics.

- **Checking** (`typecheck_check.cpp`): the blanket "references cannot be
  returned" rejection is now origin-aware. A `T ref` return type with declared
  origins (`returnOriginOrdinals_`/`returnOriginDisplay_`, set in
  `checkFunction`) admits a returned reference whose *origin root*
  (`originRootLocalOf`: walks Grouped/Index/Member/`ref`/`ref mut`/`*` to the
  root local) is a parameter whose ordinal is declared. A bare `T ref` (no
  declared origins) is still non-returnable, with an updated message pointing
  at declaring `T ref(a | b)`.

- **Tests** (`test/origin_contracts_test.cpp`, 10 cases): positives —
  choose-like branch origins (`a | b`), first-like borrow-into-param array,
  whole-reference passthrough under its origin, single-origin identity,
  cross-function same-name parameter ordinals; negatives — returning a param
  outside the origin set, returning a borrowed local, a non-parameter declared
  origin, undeclared-origin still non-returnable; plus an E2E runtime case
  (`first`/`choose` compiled and executed). `test/borrow_check_test.cpp`
  updated to the new undeclared-origin message.

- **Contract example** `example/origin_contracts.ng`: `first`/`choose`/
  `pass_through` under `items`/`a | b` origins; 3 printed `true`s end to end.

- **Verification**: full suite 570/570 (3672 assertions); ctest 571/571
  (includes the examples sweep); guard raised for ast.hpp 977 → 980 (origins
  list on `ScopedReferenceTypeSyntax`) with justification.
